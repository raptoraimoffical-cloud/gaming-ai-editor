# Source pictures and Pokemon entrance audio

The production image failure was not a global Google quota. An image-beat validator could throw on one mismatched model quote/index before the normal exact-span correction ran. Quick Draft then discarded all actor actions and pictures for that passage. Pictures now compile independently, using supplied narration words; legacy unique quotes receive the same exact-span correction as other actions. One rejected picture or animation cannot discard valid siblings, and downloaded asset keys retain their original action indexes after validation.

Source pictures have a separate approximately two-second planning budget. The asset resolver tries all qualified Google originals rather than only four candidates, then correctly identified cached originals, native item/character files and published mechanic images. Cached source files do not require the same old search query. Generated build sheets and prior authored timelines are excluded. Missing sources remain disclosed; there are no placeholder photos or invented description cards.

Focus photos occupy 86% of the canvas width above automatic subjects. Support photos use a separate lane with smoothly resized continuing characters. Published evidence sits above protected battle actors. The prior zigzag dash is replaced by anticipation, acceleration, overshoot, settling and recovery with continuous easing. New picture slots do not consume character-action slots.

Pokemon cries are scheduled from finished visible image ranges in Pokemon game segments, after the final layout and required-image execution. Continuous replicas and scene splits coalesce; actual disappearances and re-entries trigger another cry. Simultaneous roster entrances each receive a short, staggered recorded cry at a lower mix level. Only raw recorded audio is cached. Forms without a dedicated available cry use their verified species recording, with that provenance retained. Explicit disable settings and manual audio deletions remain supported. Cries no longer suppress coordinated pop/impact cues.

Validation:
- `node --test` covers image timing, independent failure handling, all-candidate downloads, source identity, layout, cry re-entries, multi-game isolation, simultaneous reveals, unavailable sources and manual sound deletion.
- `scripts/verify-source-picture-cues-live.mjs` uses the configured qwen3:8b model and the actual recorded Eric Rios passage, downloads no replacement voice and saves no project. The repaired production planner delivered the identified original photo at 8.3s, rendered at 86% canvas width. This diagnostic has no Google API key; other proposed source queries were unavailable. It does not establish full-video density or studio-quality animation.
- `scripts/verify-pokemon-entrance-cries.mjs` downloads the actual Pikachu recording, verifies three entrances of the same species, verifies undo/redo, and exports a native 1080x1920 MP4 with the original narration excerpt. The original MP3 remains byte-for-byte unchanged. No project is saved.
- `scripts/verify-source-picture-story-live.mjs` is the longer full-generation diagnostic. Its pre-repair run exposed the all-passages rejection. Do not describe that failed run as a successful full-video validation.
