# Sourced mechanic images

Automatic edits use published images for Pokemon move and ability descriptions, and original game type icons. Google searches keep the downloaded original, attribution and source URL. Trained vision must see the matching move/ability name and readable description, or identify the requested type icon. Approved images are cached; later edits reuse the file, not a former composition.

Generated mechanic cards and badges are removed when no matching source image is available. The editor and export also suppress legacy automatic cards. Explicitly authored manual objects, real statistical charts, captions and character/effect animation remain supported. Literal crown/weather accents also require a sourced picture rather than an SVG substitute.

Type recognition uses local Pokemon context and phrases such as Fire-type, Electric Pokemon, Water moves, resistance and weakness. Ordinary words such as a normal day, a dark room or a small bug do not trigger type icons. Images appear at their spoken word cues; type icons occupy a small supporting area.

The AI Changes request “Use images for moves, abilities and types instead of making cards” performs a source-image pass on the selected scenes, without running a full creative remake. Whole remakes, selective regeneration and instruction regeneration enforce the same image policy. Pipeline evidence lists successful sources, rejected candidates and missing images. Missing images are disclosed, never replaced with a pretend official panel.

Verification uses controlled Google search/download and vision fixtures to check wrong-name rejection, original file/credit preservation, caching, timing, duplicate prevention, legacy suppression, selective edits and Undo/Redo. It does not claim live SerpApi or real vision accuracy for every returned image. Existing provider configuration is retained.
